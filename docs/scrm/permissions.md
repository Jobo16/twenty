# 租户、成员与权限领域规则

本文记录 `packages/scrm-domain` 中租户隔离、成员状态和权限判定的实现口径。应用服务调用这些规则，但不在这里实现中间件、存储或审计持久化。

## 租户边界

一家客户企业对应一个租户，也对应一个 Twenty Workspace。领域层把两者当作同一个隔离边界，`tenantId` 与既有代码中的 `workspaceId` 是同一个值，映射只发生在 `decideResourceAccess` 一处。

判定必须显式拿到**被保护数据所属的租户**，不允许从操作者或会员关系反推：

- 资源租户无法解析（`null` 或空白）→ 拒绝。
- 操作者租户无法解析 → 拒绝。
- 两者不一致 → 拒绝，即使归属人就是操作者本人。

`null` 表示“解析不出来”，空字符串在进入判定时被归一化为 `null`。这两种情况都必须拒绝，不能退化成“范围更小的允许”。

## 判定顺序

`decideResourceAccess` 依次执行下列关卡，任何一关不通过即返回拒绝，并带上稳定的原因码：

| 顺序 | 关卡 | 拒绝原因码 |
| --- | --- | --- |
| 1 | 资源租户可解析 | `TENANT_CONTEXT_REQUIRED` |
| 2 | 操作者租户可解析 | `SUBJECT_TENANT_REQUIRED` |
| 3 | 租户处于可服务状态（仅 `ACTIVE`） | `TENANT_NOT_OPERABLE` |
| 4 | 已解析出成员关系 | `MEMBERSHIP_REQUIRED` |
| 5 | 成员处于可操作状态（仅 `ACTIVE`） | `MEMBER_NOT_OPERABLE` |
| 6 | 成员关系属于操作者租户 | `MEMBERSHIP_TENANT_MISMATCH` |
| 7 | 角色持有该动作能力 | `ACTION_NOT_GRANTED_TO_ROLE` |
| 8 | 租户一致且资源在数据范围内 | `TENANT_MISMATCH` / `RESOURCE_OUT_OF_SCOPE` |
| 9 | 通过 | 返回 `allowed: true` 与生效的 `dataScope` |

能力（第 7 关）先于数据范围（第 8 关）判定，因此“角色本来就不能做这件事”会盖过“这一行恰好也不在范围内”，调用方拿到的是最外层、可行动的原因。放弃这两个原因的先后顺序会让同一请求在不同数据下返回不同原因码。

拒绝使用原因码而非文案，调用方、测试和审计记录共享同一套词汇。

## 角色能力

能力回答“这个角色能否执行该动作”，与“能访问哪些行”是两件事。

| 角色 | CUSTOMER_READ | CUSTOMER_UPDATE | CUSTOMER_CLAIM | CUSTOMER_TRANSFER | CUSTOMER_EXPORT |
| --- | --- | --- | --- | --- | --- |
| SALES | 是 | 是 | 是 | 否 | 否 |
| TEAM_LEAD | 是 | 是 | 是 | 是 | 否 |
| DEPARTMENT_HEAD | 是 | 是 | 是 | 是 | 否 |
| TENANT_ADMIN | 是 | 是 | 是 | 是 | 是 |
| PLATFORM_OPERATOR | 否 | 否 | 否 | 否 | 否 |

导出是第一个对销售角色关闭的动作，因为它成批把数据带出租户。平台运维不持有任何业务能力：跨租户操作是单独授权的审计能力，不由角色字符串隐含。

## 数据范围

角色决定可达到的最宽范围，范围再与该资源的归属投影比较：

| 范围 | 生效角色 | 判定依据 |
| --- | --- | --- |
| `OWN` | SALES | 资源归属人等于操作者本人 |
| `TEAM` | TEAM_LEAD | 资源归属人所在团队等于操作者团队 |
| `DEPARTMENT` | DEPARTMENT_HEAD | 资源归属人所在部门等于操作者部门 |
| `WORKSPACE` | TENANT_ADMIN | 租户一致即通过 |

范围判定始终使用资源的**归属投影**（当前归属人、团队、部门），并复用既有的 `isAllowedByScope` 与角色范围表，不在此处重新实现一套比较逻辑。

边界情形：

- 未分配客户对 `OWN` 与 `TEAM` 均不可见，因为没有归属人可比较。
- 组长或部门负责人自身没有团队/部门时，`TEAM` 与 `DEPARTMENT` 判定失败，不会退化为全租户。
- 平台运维的角色范围为 `null`，即使数据范围检查被绕过也不会得到业务数据。

## 成员与组织

`MemberMembership` 是人与一个租户的连接，携带角色、状态、团队和部门。团队与部门可以为空，`null` 表示“尚未归属”而不是“全部”。

成员关系自带租户：把从其他租户目录解析出的成员与调用方的租户上下文拼在一起，会静默交出那个租户的数据范围，因此两者始终比较，而不是信任调用方传入的租户。

## 不在本层范围

- Twenty 鉴权中间件、控制器与 GraphQL 接入。
- 数据库迁移和持久化。
- 成员同步与组织变更回调。
- 字段敏感度、会话内容权限、批量操作策略。
- 通用 ABAC 条件语言与审计落库。

这些属于 P1 的其余条目和后续阶段；本层只提供可判定的规则。
