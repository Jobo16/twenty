# SCRM 任务看板

这是共享 `test` 分支的唯一任务入口。所有 Agent 在同一个仓库目录中工作，不创建 Issue、PR、功能分支或 worktree。任务行中的状态文字就是认领锁和验收记录。

## 状态

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 待办 | 范围、文件边界和前置条件明确，可开始 | Agent 在本行写入名字并改为“进行中” |
| 进行中 · 姓名 | 该 Agent 正在修改指定范围 | 其他人不得修改同一范围 |
| 待验收 | 已完成实现和本任务检查 | 负责人审查共享目录中的改动 |
| 已完成 | 已审查、提交并纳入目标分支 | 可作为后续任务的稳定前置条件 |
| 阻塞 | 缺少产品决定、前置实现或存在范围冲突 | 写明阻塞原因和需要的决定 |

## 使用方式

1. 开始前确认本地在 `test`，并查看 `git status`，不能清理或覆盖已有改动。
2. 只可领取“待办”任务：把状态改为“进行中 · <姓名>”，再编辑其文件边界。
3. 完成后把状态改为“待验收”，在“交付 / 验收”列补充行为、实际执行的命令、数据库或配置影响和未覆盖范围。
4. 负责人审查后提交到 `test` 并将状态改为“已完成”。当 `test` 可发布时，再推进同一修订到 `main`。

任务必须可独立完成，且同一时间的任务不能修改同一文件、根配置、迁移或测试夹具。出现重叠时先标为“阻塞”，由负责人重新拆分。
